## fig1_signed_vs_folded.png — sign-folding diagnostic (R04 vs R03)

**Source JSONs**

- R04: `action3_coherence.json` → key `"04"` (list of 610 frames).
  Per frame used: `"n"` (signed north m), `"e"` (signed east m).
- R03: `action2_pool_d300.json` → key `"per_region"["03"]` (list of 34 frames).
  Per frame used: `"gt_lat"`, `"gt_lon"`, `"est_lat"`, `"est_lon"`.

**Key mappings / decisions**

- Signed north/east offset for R03 is _computed_ from
  `(est_lat, est_lon)` vs `(gt_lat, gt_lon)` using the same equirectangular
  formula as `coherence_curve.py` / `smoke_georef_bias.py`
  (`n = rad(Δlat)·R_earth`, `e = rad(Δlon)·R_earth·cos(gt_lat)`). R04 has
  pre-computed `n`/`e` in the JSON; the two are consistent.
- "Folded" magnitude = `hypot(n, e)` (sign discarded) — this is the
  sign-folding being diagnosed: the left scatter keeps the sign, the right
  histograms fold it away.

**Anomalies (worked around)**

- The task named `georef_bias.json` as the fig1 source, but that file contains
  **only a verdict** (`{"verdict": "KILLED", "regions": {"02": ..., "10": ...}}`)
  — no per-frame offsets. The n=30/32 signed-offset run documented in
  `01_action1_paper_grade_n.md` was overwritten by a later cross-domain run
  (regions 02/10, both skipped). Offsets were recovered from
  `action3_coherence.json` (R04) and `action2_pool_d300.json` (R03) instead.
- R03 and R04 come from **different sampling regimes**: R04 = full contiguous
  flight (610 frames), R03 = step-sampled d300 fix pool (34 frames). Both are
  truth-referenced (est vs GT). n is shown in the legend/hist titles.

## fig2_coherence_curve.png — temporal coherence of the R04 alias offset

**Source JSON**

- `action3_coherence.json` → key `"04"` (610 frames; per frame `"n"`, `"e"`,
  `"err"`, `"idx"`).

**Key mappings / decisions**

- Error group per frame (replicates `coherence_curve.py` line 229):
  `err < 20` → "good", `20 ≤ err < 50` → "mid", `err ≥ 50` → "alias".
- `lag_curve` reproduced exactly from `coherence_curve.py` (seed 1992, 10
  shuffle trials): for lag `L`, median `|a_i − a_{i+L}|` over same-group frame
  pairs (`idx`-aligned); "null" = same pairing after shuffling the group's
  offsets. Plotted: alias (solid) + its shuffled null (dashed), good (solid) +
  its shuffled null (dashed).
- Lag-1 annotation computed from data: `null/median = 70.1/27.5 = 2.55×`.
- **Verified**: computed curve matches `action3_coherence.log` exactly
  (27.5/70.1, 16.7/17.9, … n counts included).

**Anomalies**

- The task assumed `action3_coherence.json` contained a ready lag→median
  summary. It does not — it holds raw per-frame offsets. The curve is computed
  from those frames (defensible, reproducible, and byte-matched to the log).

## fig3_rejector_rates.png — rejection benchmark (good-kept vs fatal-kept)

**Source JSON**

- `action2_rejectors.json` → key `"pooled"` (list of rate rows).

**Key mappings / decisions**

- Per row used: `"label"` (drift d150/d300/d600), `"method"`, `"setting"`,
  `"good_kept_pct"`, `"fatal_kept_pct"`.
- **good / fatal definition** (`bench_rejectors.py`, `FATAL_M = 50`):
  `good = err_m ≤ 50 m`, `fatal = err_m > 50 m`. The two bars per rejector are
  `good_kept_pct` (blue) and `fatal_kept_pct` (vermillion).
- Rejectors with multiple swept settings are reduced to **one setting each**,
  matching the "paper table" convention in `action2_analyze.log`:
  seq-consistency `w=1 tol=100`, 3-consecutive `tol=100`, PCM `tol=100`,
  frame-alignment `tau=100`, prior-ratio (deployed/oracle) `r=1.5`.
- Horizontal dashed line at **80%** = the good-kept adoption bar
  (10th-iteration Step 3 / Action 2 doc: fatal cut ≥ 25% AND good kept ≥ 80%).
- Discrimination-ratio annotation shown **only on forward cells**
  (`good_kept_pct / fatal_kept_pct > 1`, finite, fatal_kept_pct > 0), per the
  "annotate only forward-ratio cells" instruction. `Infinity`/`NaN` ratios
  (zero-fatal cells) are intentionally not annotated.

## Global anomalies summary

1. `georef_bias.json` = verdict only; per-frame offsets absent (overwritten).
2. `action3_coherence.json` = raw R04 frames only (no R03, no lag summary).
   R03 truth-referenced offsets are only in logs, not JSON — used
   `action2_pool_d300.json` (34 frames) as the JSON-backed R03 source for fig1.
3. `action2_rejectors.json` `"pooled"` rows carry many settings per method;
   one setting selected per method (documented above).
4. Some `fatal_kept_pct` / `ratio` cells are `NaN`/`Infinity` (zero-fatal
   denominator); handled by skipping ratio annotation, not by inventing values.
